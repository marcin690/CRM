Decyzja użytkownika: osobna aplikacja zamiast przerabiania czatu Gemini.

Stan:
- Nowy app Dify "Generator grafiki": id `0bfebade-eeb2-4641-8824-9e3802cc9bc7`, publiczny URL `https://agent.w-h.pl/chat/wk5khR5lE9mihmwm`.
- Model: Nano Banana Pro, rozdzielczość domyślna 2K.
- Struktura: Start (query + files) -> LLM (Nano Banana Pro) -> Odpowiedź.

## 2. Integracja Generatora grafiki z CRM (4. kanał Asystenta AI)

Dodany jako kanał `GENERATOR_GRAFIKI` w module Asystent AI (obok Claude/ChatGPT/Gemini).

Backend:
- `AiChatApp` enum: nowa stała GENERATOR_GRAFIKI (agentCode `asystent-generator-grafiki`, model `gemini-3-pro-image-preview`), metoda `usesPoziom()` (false -> kontroler nie wysyła inputs.poziom, bo aplikacja Dify nie ma tej zmiennej), case w `modelFor`.
- `application.properties`: `dify.agent-keys.asystent-generator-grafiki=${DIFY_KEY_GENERATOR_GRAFIKI:}`.
- Obraz renderowany bez zmian w streamerze (markdown w answer).

Frontend:
- Kafel na pulpicie (AiAssistantBoxes.js), APP_META/APPS, ukryty wybór poziomu (jeden model), render obrazu (komponent img w ChatMarkdown.js + styl `.ai-img` w ai-chat.css), kolor #e0559d.

Commity: backend `23db0ca`, frontend `2561679`.

### Poprawka kolumny app (pułapka ENUM/VARCHAR)
Kolumna `app` w `ai_conversation`/`ai_usage` była wąska i niespójna między środowiskami (prod VARCHAR(16) -> "Data too long"; dev natywny MySQL ENUM bo Hibernate 6.2+ mapuje enum Javy na ENUM MySQL -> "Data truncated"), a `ddl-auto=update` tego nie naprawia.

Naprawa: encje mają `@JdbcTypeCode(SqlTypes.VARCHAR)` + length 32, migracja Flyway `V17__Widen_ai_app_to_varchar.sql` (MODIFY na VARCHAR(32) w obu tabelach). Wniosek: dodanie kolejnego kanału czatu nie wymaga już zmian w bazie. Flyway działa na prodzie; na dev kolumnę przerobiłem ręcznie.

Commit: backend `f799bc6`.

### WYMAGANE na Railway (do potwierdzenia)
Zmienna środowiskowa backendu: `DIFY_KEY_GENERATOR_GRAFIKI` (wartość = klucz API aplikacji Dify "Generator grafiki"). Bez tego kanał zwróci błąd "Asystent nie odpowiada / brak klucza". Klucz NIE jest trzymany w repo.

## 3. Załączanie PDF we wszystkich modułach Asystenta AI

Wcześniej dało się dodać tylko JPG/PNG. Teraz obrazy (PNG/JPG/WEBP/GIF) ORAZ PDF w Claude/ChatGPT/Gemini/Generator grafiki.

Backend (`AiChatService.uploadImage`): rozpoznanie typu po magic bytes (obraz lub `%PDF-`); typ dla Dify śledzony per plik (obraz -> `image`, PDF -> `document`), `resolveOwnedFiles` buduje właściwy FileRef.

Frontend: `accept` dopuszcza PDF, miniatura PDF jako kafelek zamiast podglądu obrazu, etykiety "Dodaj plik (obraz lub PDF)".

Dify (konfiguracja, nie kod): typ "Dokument" włączony we wszystkich 4 aplikacjach. 3 czaty już miały (image, document, audio, video); Generatorowi grafiki dodałem i opublikowałem.

Uwaga: dla czatów tekstowych PDF = analiza dokumentu (główny sens); dla generatora grafiki PDF raczej bez pożytku (model obrazowy), ale upload działa we wszystkich 4 zgodnie z prośbą.

Commity: backend `96499f4`, frontend `764493a`.
