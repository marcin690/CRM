# Stan prac — rozbudowa CRM WH plus (sesja 12–13.07.2026)

CRM dla **WH plus** (producent mebli hotelowych). Dwa repo:
- backend `~/IdeaProjects/crm` (Spring Boot, JPA/Hibernate Envers, MapStruct, Lombok, Java 17)
- frontend `~/IdeaProjects/crm-frontend` (React CRA, Bootstrap 5, react-select, react-quill, recharts)

Cel długoterminowy: zastąpić excelowe „karty wzorcowe" i arkusz **K2026** systemem z planowaniem produkcji (etapy, zadania, montaż, ekipy) i pełnymi finansami.

---

## ⚠️ KRYTYCZNE — ZRESTARTOWAĆ BACKEND
Bardzo wiele endpointów i pól dodano w tej sesji. Na `localhost:8080` chodzi **stara instancja** (uruchomiona przed zmianami) → nowe ścieżki zwracają 404, stąd objawy typu „brak etapów", puste raporty, brak kolumn.
- **Restart backendu** ożywia wszystko. Potem **odpalić sync Fakturowni** (przychody/% realizacji/tytuły faktur).
- Uwaga diagnostyczna: Spring Security ma `anyRequest().authenticated()` → zwraca **401 także dla nieistniejących ścieżek**, więc 401 NIE dowodzi, że endpoint istnieje (do sprawdzenia trzeba żądania z tokenem).

## Fakty techniczne (infra)
- **Schema:** dev (`application-dev.properties`) = `ddl-auto=update`, Flyway OFF. prod = `ddl-auto=update` + Flyway ON. Migracje Flyway tylko V1–V11; wszystkie nowe tabele/kolumny powstają przez Hibernate ddl-auto (bez migracji). **Dług:** brak migracji bazowych dla nowych tabel — hardening prod na później.
- **Frontend baseURL:** dev `http://localhost:8080` (`.env`), prod `https://api.w-h.pl` (`.env.production`).
- **SharePoint** (Graph app-only, tylko odczyt): env `SHAREPOINT_TENANT_ID`, `SHAREPOINT_CLIENT_ID`, `SHAREPOINT_CLIENT_SECRET`, `SHAREPOINT_SITE_URL` + Azure AD App Registration + admin consent `Sites.Read.All`/`Files.Read.All`.
- Wzorce Excela: `~/Downloads/karta wzorcowa_green park1.xlsx` (rozpiska/koszty/zamówienia jednego kontraktu) oraz `~/Downloads/CRM 2026 kopia .xlsx` (K2026 = rejestr projektów ze stopniem finansowym; R-finanse = kokpit firmy miesiąc po miesiącu).

## Zrobione — moduł projektu (zakładki, kolejność logiczna)
**Pulpit → Ogólne → Oferty → Meble → Zamówienia → Etapy → Zadania → Montaż → Finanse → Dziennik → Pliki → Komentarze → Ustawienia.**

- **Pulpit** (`PulpitTab.js`, pierwsza zakładka): KPI, pipeline etapów z paskami, najbliższe terminy (zadania+montaże), lista montaży, ostatnia aktywność, **animowany pasek „postęp w czasie"** (z dat etapów).
- **Ogólne** (`GeneralTab.js`): edytowalne switche warunków (dojazd ciężarówką/weekend/noc/list ref./strona/social), **marża deklarowana %**, **miasto**, **status projektu** (Wysłane→Zaakceptowane→W realizacji→Zrealizowane→Wstrzymane). Uwaga: flagi w `ProjectDTO` są jako **boxed Boolean** z nazwami BEZ „is" (`truckAccessible` itd.).
- **Meble** (`MebleTab.js`): rozpiska/karta informacyjna (NIE zamówienie) — nazwa, **opis główny** (pole `details`), ilość, cena jedn., kod koloru/materiał, **producent z listy Dostawców**, osoba odpowiedzialna, status ustaleń. Przycisk **„Wyślij do zamówienia"** → tworzy zamówienia (status DRAFT) + **powiadomienie** dla osoby odpowiedzialnej. Backend: `FurnitureItem`, `/projects/{id}/furniture` + `/send-to-order`.
- **Etapy** (`StagesTab.js`, master-detail): lista + panel; **zamknięcie etapu z komentarzem** (`/stages/{id}/close`+`/reopen`), zadania (checklista) z **osobą per zadanie**, terminem, statusem, **prywatnością** (widoczne tylko dla twórcy, filtr po `createdBy`), **szczegółami WYSIWYG** (react-quill), montaż jako typ zadania (tryb+daty), **koszty per etap** (AdditionalCost.stageId), **finanse per etap** (faktury po `binding.stageId`), zamówienia przypięte do etapu. Backend: `ProjectStage`(+sortOrder/notes/closedAt/closedComment), `StageTask`, endpointy `/stages` + `/stages/{id}/tasks`.
- **Zadania** (`ProjectTasksTab.js`): agregat wszystkich zadań ze wszystkich etapów + dodawanie (wybór etapu + pola).
- **Montaż** (`MontageTab.js`): **osobny byt** `Montage` (ekipa, termin od–do, **wartość netto → koszty projektu**, status). Endpointy `/projects/{id}/montages` + `/montages/schedule` (pod Gantt).
- **Finanse** (`FinanceTab.js`): plan (deklarowana/oferty/zamówienia/domówienia) vs realizacja (Fakturownia). Koszty stałe przeniesione do etapów. Faktury z **kolumną Tytuł** (`Invoice.title` synchronizowany z Fakturowni).

## Zrobione — widoki globalne
- **Lista projektów** (`ProjectsList.js`): karty z **segmentowym paskiem etapów** (zielony=zamknięty, niebieski=bieżący, szary=przyszły) + **paskiem % realizacji finansowej** + filtry (nazwa/zespół/status). Dane z `/project-stage-summaries?ids=` (+ financialPercent). Jedno zapytanie, bez N+1.
- **Ekipy** (`pages/crews/CrewsPage.js`, `/crews`, menu „Ekipy"): tabela ekip (kolor/nazwa/**kontakt na ekipie**=osoba odpowiedzialna/skład rozwijany). Zakładki **Harmonogram** (Gantt dzienny, domyślnie 30 dni, filtr Od/Do + ekipa, etykiety „Projekt·Miasto") i **Ekipy — ustawienia**. Encje `Crew`/`CrewMember`.
- **Zamówienia** (`pages/orders/OrdersOverviewPage.js`, `/orders-overview`, menu „Zamówienia"): wszystkie projekty, filtry **data/zespół/projekt/status**, **karta szczegółów** (modal). Endpoint `/orders` (`GlobalOrderController`).
- **Powiadomienia** (`layouts/NotificationBell.js`): **dzwonek w topbarze** obok „Wyloguj się" (badge, dropdown, poll 60s). REST `/notifications` (`/unread-count`, `/{id}/read`, `/read-all`). Backend powiadomień istniał (`NotificationService.createImmediateNotification` z e-mailem/SMS) — dobudowano tylko REST + UI.
- **Raport finansowy** (`pages/reports/FinancialReportPage.js`, `/reports/financial`, menu Raporty): odwzorowanie **K2026** — KPI + wykresy (recharts: słupkowy wartość vs przychód, kołowy po statusie) + tabela grupowana po zespołach z podsumowaniami + filtry. Endpoint `/reports/financial`.

## Usuwanie projektu — naprawione
`ProjectService.deleteProject` (transakcyjnie) usuwa niekaskadowane dzieci (faktury, zamówienia+pozycje, montaże, koszty, meble, komentarze, pliki SharePoint), **odpina** Event/Contact (`detachProject`), potem `deleteById` (kaskada: etapy+zadania, oferty, wiązania, dziennik+komentarze, join dostawców). Przycisk „Usuń" był — teraz działa.

## Wyrównanie/spójność UI
- Podstrony były podwójnie owinięte kontenerem (Layouts `Container fluid` + własny `container-fluid`) → treść węższa niż menu. Usunięto zbędny `container-fluid` z Projektów/Zamówień/Ekip/widoku projektu → **treść = szerokość menu**.
- Strony domeny projektu owinięte w `.project-module` → spójny styl tabel. Scoped CSS: `crm-frontend/src/components/projects/projectModule.css`. Wspólne komponenty: `components/projects/ui.js` (SectionHeader/EmptyState/Tile), `RichText.js`.
